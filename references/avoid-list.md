# Avoid-list

**This file ships empty on purpose. It is the part you have to write.**

The skill flags an ingredient because it appears below, and for no other reason. Nothing
here is a recommendation, a health claim, or the opinion of whoever wrote the skill. It is
a record of decisions you have already made, put somewhere a machine can read them.

Two rules that keep this file honest:

1. **Write it before you scan anything.** A list assembled while looking at a product you
   already distrust will agree with you. That is the failure this file exists to prevent.
2. **If you cannot say why an entry is there, take it out.** One sentence is enough. The
   sentence is what the skill repeats back to you at scan time, so a bad one shows up fast.

Keep the two kinds of entry apart when you write them down, because the skill reports them
differently and the distinction is the most useful thing it does:

- **Regulatory-restricted** — a named authority has banned or limited it somewhere. This is
  a fact about the world, and the skill will say so.
- **Personally avoided** — you would rather not eat it. This is a fact about you, and the
  skill will say that instead. It is a legitimate reason to flag something. It is not
  evidence, and the output should never dress it up as evidence.

See `avoid-list.example.md` for one filled-in version, which is one person's and not a
template for yours.

## Notes

Treat this as living. Add to it when you learn something; delete from it when a reason
stops holding. An entry you can no longer defend is worse than no entry, because the skill
will keep flagging it in a tone that sounds like a finding.
